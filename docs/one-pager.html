Apex Agent Orchestrator · Salesforce-native AI agents

AI agents your admins build - not your vendor's backlog.

A production-ready package that installs into the Salesforce org you already run, and turns agent building into point-and-click admin work: same app, same security model, same people who already own your reports, flows, and page layouts.

The situation today

Another team builds your agents. That works - but every new agent, every wording tweak, every “can it also check the attached contract?” is a request, a queue, a sprint, and a handoff. A small change costs a development cycle, same as a big one, and the knowledge of how your agents behave lives somewhere other than your team.

What it does

It runs AI agents that take action, not just answer questions - looking up records, reading attached documents, creating and updating data, handing work to other agents, and holding a real conversation with a person, all inside your existing Salesforce permissions.

Agents that do the work

Find records, read attached documents, create and update data, and complete a task end to end - not just draft a suggestion for someone else to key in.

Conversations with memory

Threads people can come back to. Agents remember durable facts and preferences across conversations, and draw lessons from how earlier runs went.

Work that actually finishes

Long, multi-step jobs aren't cut off by platform limits. An agent takes as many steps as the task needs, and can split work across several agents at once.

Bring your own AI vendor

OpenAI, Anthropic (Claude), and Azure OpenAI supported out of the box, chosen per agent from a dropdown. Switching model or vendor is a settings change - so pricing stays negotiable.

Spend control built in

Routine background work can be pointed at a cheaper model while customer-facing conversations use your best one. No code change to re-tune the mix.

Nothing in a black box

Every run and every step is stored in your org: what was asked, what the agent did, what it decided, how long it took, and which version of its instructions it was following.

Reaches your customers

One agent can be safely published to your website through a ready-made chat widget - internal reasoning stripped out, per-visitor rate limits on by default.

Fits what you already build

Trigger agents from Flow, embed them on any record page, or call them from another system. Nothing new for your team to stand up or learn.

How easy it is to run - as an admin

  • Build an agent in a form. Name it, write its instructions in plain English, pick its AI model from a dropdown, tick the boxes for what it's allowed to do, save. It's live.
  • Change it without fear. Instructions are versioned automatically - numbered, attributed, and locked once published. If the new version made things worse, rollback is one click and takes effect on the next run. No deployment, no ticket.
  • Try before you commit. A built-in Test Bench runs an agent against a saved sample and shows every step it took - and can run the same input against two versions of the instructions so you compare before making one live.
  • Watch the work happen. A live monitor lists every run with Cancel and Re-run buttons, and a step-by-step trace behind each one.
  • Manage what agents remember. One screen shows every memory an agent holds. People curate their own; admins curate everything, and review the lessons agents draw about themselves before those take effect.
  • See exactly what's granted. A catalog lists every capability and which agents have it - an access review anyone can read without opening code.

The self-service line is clear: new agents, new instructions, permissions, model choice, memory settings, and rollbacks are all admin work. A developer is needed only to add a genuinely new capability - a new kind of action, such as calling a specific external system.

Control and risk

Your security model. Agents read and write as the person running them - never beyond what that user could do themselves. Least privilege. Capabilities are granted one at a time, visible on screen. Nothing public by accident. External access stays off until an admin opts exactly one agent in. Full audit trail. Every run records the exact instructions it ran. Self-healing. Background jobs time out stuck work and clear stale data unattended. Two roles, ready to assign. Admin builds and monitors; User chats.
